## 로컬에 진입하기
이 프로젝트는 백엔드 서버가 먼저 켜져야 정상적으로 동작합니다. 프론트엔드만 띄우면 UI는 보이더라도 로그인·API·데이터베이스 기능은 동작하지 않습니다.

### 가장 안전한 로컬 실행 순서
아래 순서를 그대로 따라야 가장 안전합니다.

1. 의존성 설치
2. 백엔드 서버 실행
3. 프론트엔드 서버 실행
4. 브라우저로 3100 접속

### 정확한 실행 명령
```powershell
cd D:\Sophia_Check_System
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 1) 의존성 설치 (처음 한 번만)
npm install

# 2) 백엔드 서버 실행: 데이터베이스 부트스트랩 포함
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js

# 3) 새 터미널을 열어 프론트엔드 실행
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
npm run dev -- --host 127.0.0.1 --port 3100
```

### 빠른 실행 모음
```powershell
cd D:\Sophia_Check_System
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 처음 한 번만
npm install

# 백엔드 실행
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js

# 프론트엔드 실행
npm run dev -- --host 127.0.0.1 --port 3100

# 포트 점검
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 3100 -ErrorAction SilentlyContinue
```

#### 터미널(Windows PowerShell)에서 프로젝트 루트로 이동
예:
```powershell
cd D:\Sophia_Check_System
```

#### 실행 정책 우회
PowerShell에서 npm이 막히면 아래 먼저 실행:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

#### 의존성 설치
처음 로컬에서 실행할 때는 아래를 먼저 실행해야 합니다.
```powershell
npm install
```

#### 백엔드 서버 실행
백엔드는 반드시 먼저 실행해야 합니다.
```powershell
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue   # 필요 시 포트 점검
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js
```

정상적으로 시작되면 보통 아래처럼 출력됩니다.
```text
기본 교장 계정 생성: 박세천 / gyver0979
지출품의 서버: http://127.0.0.1:3002
```

#### 새 터미널을 하나 더 열어 프론트엔드 실행
백엔드가 이미 올라간 뒤에 실행합니다.
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
npm run dev -- --host 127.0.0.1 --port 3100
```

#### 브라우저에서 접속
주소:
```text
http://127.0.0.1:3100
```

#### 로컬 실행용 한 번에 복붙 가능한 PowerShell 전체 스크립트
아래 스크립트는 백엔드와 프론트엔드를 한 번에 정리해서 3100 포트에서 실행합니다. 만약 3100 포트가 이미 점유되어 있으면 기존 프로세스를 종료하고 다시 시작합니다.

```powershell
cd D:\Sophia_Check_System
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 기존 3002/3100 포트 점유 프로세스 확인 및 정리
$existing3002 = Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue
if ($existing3002) {
    $existing3002 | Select-Object -ExpandProperty OwningProcess -Unique | ForEach-Object {
        Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue
    }
}

$existing3100 = Get-NetTCPConnection -LocalPort 3100 -ErrorAction SilentlyContinue
if ($existing3100) {
    $existing3100 | Select-Object -ExpandProperty OwningProcess -Unique | ForEach-Object {
        Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue
    }
}

# 의존성 설치 (처음 한 번만 필요)
npm install

# 백엔드 실행
$env:PORT = '3002'
$env:HOST = '127.0.0.1'
Start-Process powershell -ArgumentList "-NoExit", "-Command", "cd 'D:\Sophia_Check_System'; `$env:PORT='3002'; `$env:HOST='127.0.0.1'; node server/index.js"

# 프론트엔드 실행
Start-Process powershell -ArgumentList "-NoExit", "-Command", "cd 'D:\Sophia_Check_System'; npm run dev -- --host 127.0.0.1 --port 3100"

Write-Host "브라우저 접속 주소: http://127.0.0.1:3100"
```

#### 로그인 정보
교장 로그인:
- 이름: 박세천
- 비밀번호: gyver0979

신규/재발급 임시 비밀번호:
- sophia00

#### 서버 종료/재시작
백엔드 서버는 실행 창에서 `Ctrl + C`로 종료할 수 있고, 다시 시작하려면 아래처럼 실행하면 됩니다.

```powershell
cd D:\Sophia_Check_System
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js
```

프론트엔드 재시작:
```powershell
cd D:\Sophia_Check_System
npm run dev -- --host 127.0.0.1 --port 3100
```

포트 충돌이 있으면 아래로 확인 후 종료합니다.

```powershell
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 3100 -ErrorAction SilentlyContinue
Stop-Process -Id <PID> -Force
```

자세한 내용은 [서버 종료재시작 방법](./서버 종료재시작 방법.md)을 참고하세요.

#### 실제로 자주 쓰는 로컬 체크리스트 10개
아래 10개는 로컬 실행 중 가장 자주 쓰는 확인 순서입니다. 문제 발생 시 먼저 아래 순서대로 확인하세요.

1. 현재 경로 확인
```powershell
Get-Location
```
프로젝트 루트가 `D:\Sophia_Check_System`인지 확인합니다.

2. Node와 npm 버전 확인
```powershell
node -v
npm -v
```
버전이 낮거나 비정상적으로 잡히면 로컬 실행이 불안정해질 수 있습니다.

3. PowerShell 실행 정책 우회
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
Windows 환경에서 `npm` 실행이 막히면 이 명령으로 일시적으로 우회할 수 있습니다.

4. 의존성 설치 상태 확인
```powershell
npm install
```
처음 실행이거나 패키지가 깨졌을 때는 이 단계부터 다시 진행합니다.

5. 백엔드 포트 점검
```powershell
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue
```
3002가 이미 사용 중이면 백엔드가 기동되지 않을 수 있습니다.

6. 프론트엔드 포트 점검
```powershell
Get-NetTCPConnection -LocalPort 3100 -ErrorAction SilentlyContinue
```
3100이 이미 점유되어 있으면 Vite가 정상 실행되지 않습니다.

7. 백엔드 시작
```powershell
cd D:\Sophia_Check_System
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js
```
백엔드가 먼저 떠야 로그인 API와 세션이 동작합니다.

8. 프론트엔드 시작
```powershell
cd D:\Sophia_Check_System
npm run dev -- --host 127.0.0.1 --port 3100
```
브라우저는 항상 3100 포트로 접속합니다.

9. SQLite 데이터 파일 상태 점검
```powershell
Get-ChildItem .\data
```
기존 DB가 깨져 있으면 실행 중 unique constraint 에러가 날 수 있습니다.

10. 브라우저로 실제 진입 확인
```text
http://127.0.0.1:3100
```
로그인 페이지가 보이는지, 이후 로그인 성공까지 확인하면 로컬 실행이 정상입니다.

#### 문제 발생 시 바로 확인하는 진단 순서
문제가 생기면 아래 순서대로 확인하는 것이 가장 빠릅니다.

1. 경로와 실행 환경 확인
```powershell
Get-Location
node -v
npm -v
```

2. 포트 점검
```powershell
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 3100 -ErrorAction SilentlyContinue
```
포트 충돌이 있으면 아래처럼 종료합니다.
```powershell
Stop-Process -Id <PID> -Force
```

3. 의존성 재설치
```powershell
cd D:\Sophia_Check_System
npm install
```

4. SQLite DB 초기화가 필요한지 확인
```powershell
Get-ChildItem .\data
```
기존 DB가 깨진 것처럼 보이면 아래를 실행합니다.
```powershell
Remove-Item .\data\app.db -Force -ErrorAction SilentlyContinue
Remove-Item .\data\app.db-shm -Force -ErrorAction SilentlyContinue
Remove-Item .\data\app.db-wal -Force -ErrorAction SilentlyContinue
```

5. 백엔드만 먼저 실행해보기
```powershell
cd D:\Sophia_Check_System
$env:PORT='3002'; $env:HOST='127.0.0.1'; node server/index.js
```
백엔드 로그에서 에러가 없으면 정상적으로 부트스트랩된 상태입니다.

6. 프론트엔드만 실행해보기
```powershell
cd D:\Sophia_Check_System
npm run dev -- --host 127.0.0.1 --port 3100
```
브라우저에서 로그인 화면이 보이는지 확인합니다.

7. 로그인 API 직접 확인
브라우저 개발자 도구 Network 탭에서 `/api/auth/login` 요청 상태를 확인합니다.

8. 최종 확인
```text
http://127.0.0.1:3100
```
로그인 화면이 나오고, 로그인 성공 후 메인 화면까지 보이면 정상입니다.

#### 최종 브라우저 검증 절차 (실제 확인 완료)
아래 절차는 로컬에서 실제로 마지막으로 확인한 정상 흐름입니다.

```text
1. 브라우저로 http://127.0.0.1:3100 접속
2. 로그인: 박세천 / gyver0979
3. 좌측 메뉴에서 사용자·직책 선택
4. 양혜련 행에서 기초과정=부장, 생활교육부=부장 지정
5. 저장 클릭
6. "저장 완료: 양혜련님의 저장된 직위는 기초과정 부장, 생활교육부 부장입니다." 메시지 확인
7. 브라우저 새로고침
8. 양혜련의 기초과정/생활교육부 값이 그대로 유지되는지 확인
```

이 절차는 실제 로컬 환경에서 검증되었고, 저장 후 새로고침에도 값이 유지됩니다.

#### 주의

- 백엔드는 3002 포트에서 실행됩니다.
- 프론트는 3100 포트에서 실행됩니다.
- 브라우저는 항상 3100 주소로 접속해야 UI를 봅니다.
- `npm run dev`은 프론트엔드용이며, 백엔드가 없으면 로그인·API 기능은 동작하지 않습니다.
- `npm install`이 안 되어 있으면 로컬 프로젝트를 실행할 수 없습니다.
- SQLite 데이터가 오래되거나 깨져 있으면 부트스트랩 단계에서 `UNIQUE constraint failed` 같은 에러가 발생할 수 있으니, 필요 시 `data` 폴더의 DB 파일을 정리한 뒤 재실행해야 합니다.
