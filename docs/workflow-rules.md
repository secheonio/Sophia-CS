# 결재 규칙 및 조직 구조

로그인·서버 저장을 구현하기 전에 확정한 업무 규칙입니다. 구현과 다르거나 바뀌는 내용이 생기면 이 문서를 먼저 고칩니다.

## 사용 범위

- 한 학교 전용입니다. 전체 사용자는 20명 내외입니다.
- 부서: 기초과정, 본과정, 심화과정, 생활교육부, 교무부, 교육과정부, 델포이, 생활관, 행정실
- 부서당 사용자는 1~5명입니다.

## 역할과 권한

| 역할 | 할 수 있는 일 |
|------|----------------|
| 기안자 | 지출품의 작성, 반려된 본인 품의 수정 후 재상신 |
| 기관장 | 소속 부서 기안자의 품의 확인·결재 |
| 교장 | 최종 결재, 사용자 추가와 직책 지정(관리자) |
| 행정실장 | 최종 결재된 품의의 지출 처리 |

다른 부서 품의의 열람 범위는 아래 열람 범위 항목을 따릅니다.

## 결재 흐름

```
기안자 → 담당 기관장 확인 결재 → 교장 최종 결재 → 행정실장 지출 처리 → 지출 완료
```

- 결재선은 기안자의 부서에서 자동으로 정해지며, 기안자가 직접 고르지 않습니다.
- 행정실은 1인 체계입니다. 행정실장이 기관장 역할로 기관장 확인 없이 교장에게 바로 상신하고, 교장 결재 후 행정실장이 지출 처리합니다.
- 기안자가 해당 부서의 기관장이면 기관장 확인 단계를 건너뜁니다.
- 기안자가 교장이면 결재 단계 없이 지출 처리만 남습니다.
- 각 단계는 순서대로만 진행됩니다.
- 대리 결재는 두지 않습니다.

## 반려

- 반려 사유는 필수 입력입니다. 사유 없이는 반려할 수 없습니다.
- 반려 사유는 기안자와 결재선 인원에게 표시됩니다.

## 첨부

- 영수증·견적서는 이미지로 첨부합니다. 이미지는 최대 5장, 장당 5MB 이하입니다.
- 재상신할 때 첨부를 추가하거나 삭제할 수 있습니다.

## 열람 범위

- 본인이 기안한 품의와 본인이 결재선에 포함된 품의만 볼 수 있습니다.
- 교장과 행정실장은 모든 품의의 결재선에 들어가므로 사실상 모든 품의를 볼 수 있습니다. 기관장은 자기 부서에서 올라온 품의만 봅니다.

## 품의 상태

| 상태 | 의미 |
|------|------|
| 결재 중 | 기관장 또는 교장 결재 차례 |
| 지출 대기 | 교장 결재 완료, 행정실장 지출 처리 차례 |
| 지출 완료 | 행정실장이 지출 처리를 마침 |
| 반려 | 어느 단계에서든 반려됨 |

반려된 품의는 기안자가 수정한 뒤 재상신하며, 결재선은 처음부터 다시 시작합니다.

## 구현 결정

- 저장소: Node 내장 SQLite (20명 규모, 설치 불필요). 필요 시 PostgreSQL로 이전 가능
- 로그인: 이메일·비밀번호, 교장이 사용자를 추가하고 임시 비밀번호를 전달
- 반려 후: 기안자가 수정 후 재상신
- 교장·행정실장은 모든 결재선에 포함되므로 사실상 모든 품의를 열람 (교체된 새 교장도 과거 품의 전체 열람)
- 교장 교체: 현재 교장이 실행, 미처리 교장 결재는 새 교장에게 이관, 완료 기록은 기존 이름 유지

## 확인 필요

- 금액 기준 추가 결재는 현재 없는 것으로 둡니다. 필요하면 알려 주세요.
- 배포 환경(인터넷 공개용 호스팅·HTTPS)을 정해야 합니다. 교장이 비밀번호를 잃는 비상 상황은 서버 관리자가 DB로 처리합니다.
