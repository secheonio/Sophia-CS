# 업무 흐름 검증 가이드

이 문서는 로그인 이후 실제 업무 흐름이 올바르게 동작하는지 검증하기 위한 체크리스트와 순서입니다. 작업은 기능 단위로 나누어 실서버에서 브라우저로 확인하면서 진행합니다.

## 1. 검증 목표
- 실제 학교 조직 구조와 역할이 앱에서 잘 반영되는지 확인
- 품의서 작성이 가능한지 확인
- 결재 흐름이 올바르게 진행되는지 확인
- 반려, 재상신, 지출 처리 기능이 동작하는지 확인
- 권한 제한이 제대로 동작하는지 확인
- 관리자 기능이 정상 동작하는지 확인

## 2. 검증 전 준비
- 교장 계정이 로그인 가능한 상태인지 확인
- 서버가 실행 중인지 확인
- 브라우저에서 http://127.0.0.1:3001 이 열리는지 확인
- 관리자가 로그인 상태인지 확인

## 3. 기본 검증 순서
1. 사용자 생성
2. 부서/직책 배정
3. 일반 사용자 로그인
4. 품의서 작성
5. 담당 기관장 승인
6. 교장 승인
7. 반려/재상신 검증
8. 첨부파일 검증
9. 권한 제한 검증
10. 관리자 기능 검증

## 4. 운영 구조 검증
실제 학교 구조와 연결되는 사용자와 부서 예시:
- 기초과정
- 본과정
- 심화과정
- 생활교육부
- 교무부
- 교육과정부
- 델포이
- 생활관
- 행정실

검증 대상:
- 교장 1명
- 행정실장 1명
- 각 부서 담당자 1명
- 일반 교직원 2~5명

## 5. 사용자/부서/직책 설정 검증
### 5.1 관리자 화면 확인
- 관리자 계정으로 로그인
- 사용자 관리 메뉴 진입
- 사용자 목록 확인
- 사용자 추가 기능 확인

### 5.2 사용자 추가 테스트
생성할 샘플 사용자 예시:
- 이름: 홍길동
- 이메일: hong@school.kr
- 부서: 본과정
- 직책: 부서장 또는 일반교직원

확인 포인트:
- 사용자가 정상 생성되는지
- 부서와 직책이 저장되는지
- 비밀번호 초기화가 되는지
- 비활성 사용자 처리 여부

## 6. 일반 사용자 로그인 검증
### 6.1 로그인 테스트
- 새로 생성한 사용자로 로그인
- 비밀번호 변경 여부 확인
- 첫 로그인 시 임시 비밀번호 변경이 필요한지 확인

확인 포인트:
- 로그인 성공
- 세션 유지
- 개인 정보 화면이나 기본 메인 화면이 보이는지

## 7. 품의서 작성 검증
### 7.1 작성 테스트
일반 사용자로 로그인한 뒤:
- 품의 작성 버튼 클릭
- 제목 입력
- 내용 입력
- 금액 입력
- 부서 선택
- 결재선 확인
- 영수증/견적서 첨부
- 저장

확인 포인트:
- 품의 목록에 생성된 품의가 나타나는지
- 상태가 올바르게 표시되는지
- 결재자가 자동으로 구성되는지
- 첨부파일이 보이는지

## 8. 결재 흐름 검증
### 8.1 기본 승인 흐름
추천 시나리오:
- 기안자: 일반 직원
- 담당 기관장: 해당 부서장
- 교장: 최종 승인
- 행정실장: 지출 처리

검증 단계:
1. 일반 직원이 품의 작성
2. 담당 기관장으로 로그인
3. 품의 확인 및 승인
4. 교장으로 로그인
5. 최종 승인
6. 행정실장으로 로그인
7. 지출 처리 완료

확인 포인트:
- 상태가 순서대로 변경되는지
- 승인 시 결재 상태가 반영되는지
- 최종 승인 후 지출 처리 단계가 보이는지

## 9. 반려와 재상신 검증
### 9.1 반려 테스트
- 담당 기관장 또는 교장이 반려
- 반려 사유 입력
- 품의 상태가 반려로 변경되는지 확인

### 9.2 재상신 테스트
- 기안자가 수정 후 다시 제출
- 상태가 재상신 또는 기안 상태로 돌아가는지 확인
- 결재선이 다시 생성되는지 확인

확인 포인트:
- 반려 사유가 저장되는지
- 재기안 후 다시 결재자가 생성되는지
- 상태 변경이 정상적인지

## 10. 첨부파일 검증
### 10.1 이미지 첨부 테스트
- 영수증 이미지 업로드
- 견적서 이미지 업로드
- 여러 장 첨부
- 파일 제한 확인

확인 포인트:
- 허용 확장자만 업로드 되는지
- 5MB 제한이 적용되는지
- 파일 수 제한이 있는지
- 이미지가 화면에 정상 표시되는지

## 11. 권한 제한 검증
### 11.1 접근 제어 테스트
- 본인이 기안하지 않은 품의를 열람하지 못하는지
- 결재선에 없는 사용자가 열람하지 못하는지
- 교장이나 부서장이 올바른 범위의 품의만 볼 수 있는지
- 관리자만 사용자 관리 기능에 접근하는지

확인 포인트:
- 허용되지 않은 접근이 차단되는지
- 권한이 없는 유저에게 적절한 메시지가 보이는지

## 12. 관리자 기능 검증
관리자(교장) 계정으로 다음 기능을 확인:
- 사용자 추가
- 사용자 비활성화
- 부서/직책 지정
- 비밀번호 초기화
- 사용자 관리 화면 접근
- 교장 교체 플로우 확인

확인 포인트:
- 사용자 관리가 정상 동작하는지
- 관리자 권한이 필요한 기능이 보호되는지
- 비밀번호 초기화 동작이 실제로 반영되는지

## 13. 실제 학교 조직 데이터 반영 검증
샘플 조직 예시:
- 기초과정
- 본과정
- 심화과정
- 생활교육부
- 교무부
- 교육과정부
- 델포이
- 생활관
- 행정실

테스트: 각 부서별 1명 이상 사용자 생성

확인 포인트:
- 부서 목록이 실제 조직 구조와 맞는지
- 결재선에서 부서별 책임자가 선택되는지
- 각 부서의 품의가 해당 부서 관리자의 결재 흐름에 맞게 반영되는지

## 17. 기록 방식
검증이 끝날 때마다 아래처럼 기록하면 좋습니다.
- 검증 날짜
- 검증 시나리오
- 결과
- 발견된 문제
- 수정 내용
- 재검증 결과

예시:
```text
2026-10-26
시나리오: 일반 직원 품의 작성 및 담당 기관장 승인
결과: 성공
기록: 결재 상태가 정상적으로 변경됨
다음 조치: 반려 시나리오 확인
```

## 18. 결론
이 문서는 실제 업무 흐름을 브라우저에서 검증하는 기준서입니다. 각 기능을 하나씩 확인하고, 실제로 로그인 후 품의 작성부터 승인/반려/재상신/지출까지 이어지는 흐름을 확인하는 것이 목적입니다.

로그인 완료 상태에서 시작하는 실제 업무 검증은, 앱의 기능이 비즈니스 로직과 맞는지를 확인하는 가장 중요한 단계입니다.
