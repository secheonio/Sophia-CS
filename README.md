# 지출품의 결재 프로그램

한 학교 안에서 쓰는 지출품의 결재 웹 프로그램입니다.
기안자 → 담당 기관장 확인 결재 → 교장 최종 결재 → 행정실장 지출 처리 순서로 진행됩니다.

## 기능

- 이메일·비밀번호 로그인 (서버 세션, 로그인 시도 제한)
- 교장(관리자)이 사용자 추가, 소속·직책 지정, 사용 중지, 비밀번호 초기화
  - 임시 비밀번호는 추가·초기화 직후 한 번만 표시되며, 첫 로그인 때 변경해야 합니다.
- 기안, 결재선 자동 생성, 승인, 반려(사유 필수), 수정 후 재상신, 지출 처리
- 영수증·견적서 이미지 첨부 (PNG·JPG·GIF·WEBP, 최대 5장, 장당 5MB)
- 열람 제한: 본인이 기안했거나 결재선에 포함된 품의만 서버에서 조회·열람 허용
- 내 결재함, 상태·부서 필터, 검색

규칙과 조직 구조는 [결재 규칙 및 조직 구조](./docs/workflow-rules.md)를 참고하세요.

## 구성

- `src/`: React + TypeScript + Vite 화면
- `server/`: Node.js + Express API, 내장 SQLite(`node:sqlite`) 저장소
- 데이터 파일: `data/app.db` (Git에 올라가지 않음)

데이터베이스는 약 20명 규모에 맞춰 PostgreSQL 대신 Node 내장 SQLite를 사용합니다. 별도 DB 설치가 필요 없고, 이후 필요하면 PostgreSQL로 옮길 수 있습니다.

## 첫 교장 계정 만들기

서버를 처음 설치한 뒤 한 번만 실행합니다. 이메일은 교장이 실제로 쓸 주소로 정하세요(로그인 아이디로 쓰이며 메일은 발송되지 않습니다).

- 명령을 실행하면 비밀번호를 묻습니다. 입력(화면에 표시되지 않음)하고 한 번 더 확인하면 그 비밀번호로 바로 로그인할 수 있습니다.
- 비밀번호를 비워 두면 임시 비밀번호가 한 번 출력되고, 첫 로그인 때 변경하게 됩니다.
- 자동화가 필요하면 환경 변수 `INITIAL_ADMIN_PASSWORD`로 비밀번호를 줄 수 있습니다.
- 교장 계정이 이미 있으면 실행되지 않습니다. 이후 사용자 추가와 교장 교체는 화면에서 합니다.

## 실행 (개발)

필요한 것: Node.js 22.13+ (개발은 24에서 확인)

```powershell
npm install
$env:PORT = '3002'; $env:HOST = '127.0.0.1'; node server/index.js   # 로컬 API 서버 (http://127.0.0.1:3002)
npm run dev                                                       # 화면 (http://127.0.0.1:3100, /api는 3002로 전달)
```

- 로컬 개발 환경에서는 학교 Ubuntu SSH 터널이 3001 포트를 점유할 수 있으므로, 로컬 API는 3002를 기본으로 둡니다.
- 실제 운영 배포는 3001 또는 프록시 뒤의 공개 포트를 사용합니다.
- 교장(관리자) 로그인은 학교 초기 관리자 계정으로 진행하고, 사용자 추가 화면에서 다중 소속/다중 직책을 선택해 저장할 수 있습니다.

### 로컬 배포 전 점검

```powershell
node --test server/app.test.js
node_modules\typescript\bin\tsc -b
node_modules\vite\bin\vite.js build
```

- 로그인/권한/결재 흐름/관리자 기능을 검증한 뒤 운영 서버로 옮깁니다.
- 학교 서버에 배포할 때는 HTTPS 뒤에서만 운영하고, 쿠키는 `secure` 모드로 동작하도록 설정합니다.

## 실행 (운영)

```powershell
npm run build
$env:NODE_ENV = 'production'; npm run server
```

- 운영에서는 반드시 HTTPS 뒤에서 실행하세요. 로그인 쿠키가 `secure`로 발급됩니다.
- 리버스 프록시(Nginx, 클라우드 로드밸런서 등) 뒤라면 `TRUST_PROXY=1`을 설정하세요.
- 환경 변수: `PORT`(기본 3001), `HOST`(기본 127.0.0.1), `DATABASE_FILE`(기본 `data/app.db`)
- `data/` 폴더(DB 파일)를 정기적으로 백업하세요. 비밀번호 해시와 영수증 이미지가 들어 있습니다. `npm run backup`(= `node server/backup.js [폴더] [보관일수]`)은 운영 중에도 안전한 복사본을 만듭니다.
- 학교 서버(Ubuntu + Caddy + 자동 백업) 설치 절차는 [배포 안내서](./docs/deployment.md)를 따르세요.

## 검증

```powershell
node --test server/app.test.js   # API 권한·보안 규칙 테스트
npm run build                    # 타입 검사 + 빌드
```

## 알려진 제한

- 교장 교체: 현재 교장이 직접 실행합니다. 새 교장(신규 등록 또는 기존 사용자)에게 직책과 관리자 권한이 넘어가고, 기존 교장 계정은 사용 중지됩니다. 아직 처리되지 않은 교장 결재는 새 교장에게 이관되고, 완료된 결재는 기존 교장 이름으로 남습니다. 교장은 과거 품의를 모두 열람합니다. 결재 중인 품의가 있는 기존 사용자와 행정실장은 새 교장으로 지정할 수 없습니다.
- 초대 이메일·알림 메일은 없습니다. 관리자가 임시 비밀번호를 직접 전달합니다.
- 금액별 추가 결재, 대리 결재는 없습니다(요구사항에서 제외).
- 인터넷 공개는 [배포 안내서](./docs/deployment.md)의 구성(학교 Ubuntu 서버, Caddy HTTPS, 자동 백업)을 따릅니다. 아직 실제 서버에는 설치하지 않았습니다.
